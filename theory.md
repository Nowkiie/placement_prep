## ООП

### Принципы ООП

#### 1. Наследование
- **Определение:** позволяет переиспользовать методы родительского класса.
- **Цель:** устранение дублирования кода → улучшение читаемости и поддержки.

#### 2. Инкапсуляция
- **Определение:** скрывает состояние объекта внутри методов.
- **Цель:** контроль доступа, проверка входящих значений.

#### 3. Полиморфизм
- **Определение:** изменение поведения в зависимости от типа объекта.
- **Связано:** с приведением типов и выбором вызываемого метода.

#### 4. Абстракция
- **Определение:** фокус на том, *что* делает объект, а не *как*.
- **Цель:** упрощение кода и проектирования.

---

### Композиция vs Наследование

| Отношение | Принцип | Описание |
|-----------|---------|----------|
| **Композиция** | *has-a* | Внутри класса создаётся экземпляр другого класса. |
| **Наследование** | *is-a* | Класс является наследником другого класса. |

> **Рекомендация:** предпочитайте **композицию** — она даёт гибкость и избегает сложных иерархий.

## Контракт equals() и hashCode()

### equals()
- Сравнивает объекты **по содержимому**.
- По умолчанию — сравнивает **ссылки** (как `==`).
- Исключение: `String` уже переопределяет `equals()`.

### hashCode()
- Возвращает `int` — хэш-код объекта.
- По умолчанию — вычисляется на основе **адреса в памяти**.

### Важные соглашения
- Если `equals()` → `true`, то `hashCode()` **должны совпадать**.
- Если `equals()` → `false`, `hashCode()` **могут совпадать** (коллизия).

### Что сломается, если не переопределить hashCode()?
- `HashMap`, `HashSet`:
  - Одинаковые объекты будут дублироваться.
  - Поиск по ключу не сработает.

### == vs equals()
- `==` — сравнение **ссылок**.
- `equals()` — сравнение **содержимого** (если переопределён).

## Immutable (Неизменяемые объекты)

**Определение:** объект, состояние которого **нельзя изменить** после создания.

### Как создать?
1. Не писать сеттеры.
2. Класс — `final`.
3. Все поля — `private` и `final`.

### Модификатор final
- **Переменная** — нельзя изменить ссылку.
- **Метод** — нельзя переопределить.
- **Класс** — нельзя наследовать.

### Защитные копии
- Для изменяемых полей (коллекции, массивы).
- В конструкторе и геттере возвращать **копию**.
- В Java 10+ — `copyOf()` для немодифицируемых коллекций.

## Многопоточность

### Создание потоков
- Наследование от `Thread` — не рекомендуется (нарушает *is-a*).
- Используйте интерфейсы `Runnable` или `Callable`.

### Методы управления потоками

| Метод | Действие | Особенности | Применение |
|-------|----------|-------------|------------|
| `sleep()` | Останавливает поток | **Не снимает блокировки** | Задержки, опросы |
| `wait()` | Усыпляет поток | **Снимает блокировки**, ждёт `notify()` | Поставщик-потребитель |
| `join()` | Ждёт завершения другого потока | — | Когда нужны результаты |

### volatile vs synchronized

| Ключевое слово | Назначение | Особенности |
|----------------|------------|-------------|
| `volatile` | Видимость изменений для всех потоков | Не гарантирует взаимное исключение |
| `synchronized` | Синхронизация потоков | Предотвращает гонки |

### Способы использования synchronized
- На экземпляре (метод объекта).
- На статическом методе (защита статических полей).
- Внутри блока (гибкая синхронизация).

## Коллекции

### Иерархия
- `Collection` наследует `Iterable` → все коллекции умеют создавать итератор.
- Основные интерфейсы: `List`, `Set`, `Queue`.

---

### List (упорядоченная, с дубликатами)

| Класс | Структура | Сложность |
|-------|-----------|-----------|
| `ArrayList` | Динамический массив | Получение: O(1)<br>Вставка/удаление в начале: O(n)<br>Вставка/удаление в конце: O(1) |
| `LinkedList` | Двусвязный список | Получение: O(n)<br>Вставка/удаление: O(1) (в середине — сложнее)<br>Память: больше |
| `Vector` / `Stack` | Устаревшие | Не использовать |

---

### Map (ключ-значение)

| Класс | Особенности |
|-------|-------------|
| `HashMap` | Базовая реализация |
| `LinkedHashMap` | Сохраняет **порядок добавления** |
| `TreeMap` | Сортировка (красно-чёрное дерево) |

---

### Set (уникальные элементы)

| Класс | Внутренняя реализация |
|-------|------------------------|
| `HashSet` | Внутри — `HashMap` |
| `LinkedHashSet` | Внутри — `LinkedHashMap` + порядок |
| `TreeSet` | Внутри — `TreeMap` (сортировка) |

> Уникальность обеспечивается через `hashCode()` и `equals()`.

## Строки (String)

### Неизменяемость
- Строки неизменяемы для безопасности, производительности и экономии памяти.
- `s += "test"` → создаётся **новый объект**.

### StringBuffer vs StringBuilder

| Класс | Потокобезопасность | Скорость |
|-------|---------------------|----------|
| `StringBuffer` | Да (синхронизирован) | Медленнее |
| `StringBuilder` | Нет | Быстрее |

### Устройство
- Внутри — массив `char[]` с начальным размером 16.
- При переполнении — новый массив `размер * 2 + 2`.

---
