# 1. Принципы разработки

## SOLID

### S — Single Responsibility (Принцип единственной ответственности)
- **Определение:** один класс = одна причина изменения.
- **Суть:** класс должен отвечать только за одну задачу.
- **На собеседовании:** «Приведи пример нарушения в реальном коде».

### O — Open/Closed (Принцип открытости/закрытости)
- **Определение:** открыт для расширения, закрыт для изменения.
- **Пример:** добавление нового типа платежа без правки старого кода.

### L — Liskov Substitution (Принцип подстановки Барбары Лисков)
- **Определение:** наследник не должен ломать контракт родителя.
- **Классика:** `Square extends Rectangle` — почему ломается.

### I — Interface Segregation (Принцип разделения интерфейсов)
- **Определение:** много узких интерфейсов лучше одного «толстого».

### D — Dependency Inversion (Принцип инверсии зависимостей)
- **Определение:** зависимость от абстракций, а не от реализаций.
- **Связь со Spring DI.**

---

## KISS / DRY / YAGNI

- **KISS** — не усложняй. Спросят: «Когда абстракция вредит?»
- **DRY** — не дублируй знания, а не код. Важный нюанс: преждевременная дедупликация опаснее дублирования.
- **YAGNI** — не делай то, что не нужно сейчас.
- **Бонус:** Boy Scout Rule, Law of Demeter, Composition over Inheritance.

---

## Что реально спрашивают на мидла

«Расскажи, где ты нарушал SOLID и почему это было оправдано» — проверяют не знание, а инженерное суждение.

# 2. Java Core — полный список тем

## 2.1. ООП и базовое

### Принципы ООП

#### 1. Наследование
- **Определение:** позволяет переиспользовать методы родительского класса.
- **Цель:** устранение дублирования кода → улучшение читаемости и поддержки.

#### 2. Инкапсуляция
- **Определение:** скрывает состояние объекта внутри методов.
- **Цель:** контроль доступа, проверка входящих значений.

#### 3. Полиморфизм
- **Определение:** изменение поведения в зависимости от типа объекта.
- **Связано:** с приведением типов и выбором вызываемого метода.

#### 4. Абстракция
- **Определение:** фокус на том, *что* делает объект, а не *как*.
- **Цель:** упрощение кода и проектирования.

---

### Композиция vs Наследование

| Отношение | Принцип | Описание |
|-----------|---------|----------|
| **Композиция** | *has-a* | Внутри класса создаётся экземпляр другого класса. |
| **Наследование** | *is-a* | Класс является наследником другого класса. |

> **Рекомендация:** предпочитайте **композицию** — она даёт гибкость и избегает сложных иерархий.

---

### equals() / hashCode() — контракт

#### equals()
- Сравнивает объекты **по содержимому**.
- По умолчанию — сравнивает **ссылки** (как `==`).
- Исключение: `String` уже переопределяет `equals()`.

#### hashCode()
- Возвращает `int` — хэш-код объекта.
- По умолчанию — вычисляется на основе **адреса в памяти**.

#### Важные соглашения
- Если `equals()` → `true`, то `hashCode()` **должны совпадать**.
- Если `equals()` → `false`, `hashCode()` **могут совпадать** (коллизия).

#### Что сломается, если не переопределить hashCode()?
- `HashMap`, `HashSet`:
  - Одинаковые объекты будут дублироваться.
  - Поиск по ключу не сработает.

#### == vs equals()
- `==` — сравнение **ссылок**.
- `equals()` — сравнение **содержимого** (если переопределён).

---

### toString(), clone() (shallow vs deep)

- **toString()** — возвращает строковое представление объекта. По умолчанию: `ClassName@hashCode`.
- **clone()** — создаёт копию объекта.
  - **Shallow copy** — копируются ссылки на вложенные объекты.
  - **Deep copy** — рекурсивно копируются все вложенные объекты.

---

### Абстрактный класс vs интерфейс (включая default/static методы)

| Критерий | Абстрактный класс | Интерфейс |
|----------|-------------------|-----------|
| Наследование | Только одно | Много |
| Поля | Могут быть любые | Только `public static final` |
| Методы | Абстрактные и конкретные | Абстрактные, `default`, `static` |
| Конструкторы | Есть | Нет |
| Когда использовать | Общая логика + состояние | Контракт поведения |

---

### Вложенные, внутренние, анонимные классы, лямбды

- **Вложенные (nested)** — статические, не имеют доступа к `this` внешнего класса.
- **Внутренние (inner)** — нестатические, имеют доступ к полям внешнего класса.
- **Анонимные** — без имени, создаются на месте, обычно для реализации интерфейса.
- **Лямбды** — краткая форма для функциональных интерфейсов.

## 2.2. Строки

### String pool, immutability

- **String Pool** — хранит **уникальные строковые литералы** в куче.
- Экономит память за счёт переиспользования.

```java
String s1 = "java";
String s2 = "java";     // ссылка из пула
String s3 = new String("java"); // новый объект в куче
```

- **Неизменяемость:**
  - Строки неизменяемы для безопасности, производительности и экономии памяти.
  - `s += "test"` → создаётся **новый объект**.

---

### String vs StringBuilder vs StringBuffer

| Класс | Потокобезопасность | Скорость | Изменяемость |
|-------|---------------------|----------|--------------|
| `String` | Да (immutable) | Медленный при конкатенации | Нет |
| `StringBuffer` | Да (синхронизирован) | Медленнее | Да |
| `StringBuilder` | Нет | Быстрее | Да |

- **Устройство StringBuilder/StringBuffer:**
  - Внутри — массив `char[]` с начальным размером 16.
  - При переполнении — новый массив `размер * 2 + 2`.

---

### intern(), конкатенация в цикле

- **intern()** — помещает строку в String Pool, возвращает ссылку из пула.
- **Конкатенация в цикле** — используйте `StringBuilder`, иначе создаётся много мусорных объектов.

## 2.3. Коллекции

### Иерархия
- `Collection` наследует `Iterable` → все коллекции умеют создавать итератор.
- Основные интерфейсы: `List`, `Set`, `Queue`, `Deque`, `Map`.

---

### List (упорядоченная, с дубликатами)

| Класс | Структура | Сложность |
|-------|-----------|-----------|
| `ArrayList` | Динамический массив | Получение: O(1)<br>Вставка/удаление в начале: O(n)<br>Вставка/удаление в конце: O(1) |
| `LinkedList` | Двусвязный список | Получение: O(n)<br>Вставка/удаление: O(1) (в середине — сложнее)<br>Память: больше |
| `Vector` / `Stack` | Устаревшие | Не использовать |

---

### Map (ключ-значение)

| Класс | Особенности |
|-------|-------------|
| `HashMap` | Базовая реализация |
| `LinkedHashMap` | Сохраняет **порядок добавления** |
| `TreeMap` | Сортировка (красно-чёрное дерево) |

- **HashMap: устройство:**
  - Массив бакетов + связные списки.
  - С Java 8: при длине списка > 8 — преобразуется в красно-чёрное дерево (treeify).
  - Load factor по умолчанию 0.75.
- **ConcurrentHashMap:**
  - Потокобезопасная реализация.
  - Отличие от `Collections.synchronizedMap`: сегментированная блокировка (до Java 8), CAS-операции.
- **LinkedHashMap** — можно построить LRU-кэш (переопределив `removeEldestEntry`).

---

### Set (уникальные элементы)

| Класс | Внутренняя реализация |
|-------|------------------------|
| `HashSet` | Внутри — `HashMap` |
| `LinkedHashSet` | Внутри — `LinkedHashMap` + порядок |
| `TreeSet` | Внутри — `TreeMap` (сортировка) |

> Уникальность обеспечивается через `hashCode()` и `equals()`.

## 2.4. Generics

- **Инвариантность** — `List<Number>` не является `List<Integer>`.
- **Ковариантность** — `? extends T` (можно читать).
- **Контравариантность** — `? super T` (можно писать).
- **PECS** — Producer Extends, Consumer Super.
- **Type erasure** — стирание типов во время компиляции, информация о generic-типах недоступна в runtime.
- **Bridge-методы** — генерируются компилятором для сохранения полиморфизма после erasure.

---

## 2.5. Исключения

- **Checked** — должны быть обработаны или объявлены (наследники `Exception`, кроме `RuntimeException`).
- **Unchecked** — `RuntimeException` и наследники, не требуют обработки.
- **Error** — `OutOfMemoryError`, `StackOverflowError` — не ловить.
- **try-with-resources** — автоматическое закрытие ресурсов, реализующих `AutoCloseable`.
- **Подавленные исключения** — `addSuppressed()`.
- **Когда не ловить Exception** — не глотать исключения, не ловить `Throwable`, не использовать для управления потоком.

---

## 2.6. Функциональщина

- **Лямбды** — анонимные функции.
- **Функциональные интерфейсы** — один абстрактный метод (`@FunctionalInterface`).
- **Stream API:**
  - **Intermediate** — `filter`, `map`, `flatMap` (lazy).
  - **Terminal** — `collect`, `forEach`, `reduce` (запускают pipeline).
- **Optional** — контейнер для значения, которое может быть `null`. Антипаттерн: использовать как поле класса или параметр.
- **Collectors** — `toList`, `toSet`, `groupingBy`, `partitioningBy`.
- **flatMap vs map** — `map` 1:1, `flatMap` 1:N (разворачивает вложенные структуры).

---

## 2.7. I/O и NIO

- **Байтовые потоки** — `InputStream`/`OutputStream`.
- **Символьные потоки** — `Reader`/`Writer`.
- **BufferedReader, InputStreamReader** — для чтения с буферизацией и указанием кодировки.
- **NIO:**
  - `Channel` — двунаправленный канал.
  - `Buffer` — контейнер для данных.
  - `Selector` — мультиплексирование.
- **Сериализация:**
  - `Serializable`, `serialVersionUID`.
  - Почему избегают: хрупкость, проблемы с безопасностью, несовместимость версий.

---

## 2.8. Reflection и аннотации

- **Class, Method, Field, invoke** — доступ к метаданным и вызов методов в runtime.
- **Свои аннотации** — `@interface`, `@Retention`, `@Target`.
- **Retention policy** — `SOURCE`, `CLASS`, `RUNTIME`.
- **Где используется** — Spring (DI, AOP), Hibernate (маппинг).

# 3. Многопоточность

## 3.1. Основы

### Создание потоков
- Наследование от `Thread` — не рекомендуется (нарушает *is-a*).
- Используйте интерфейсы `Runnable` или `Callable`.

### Методы управления потоками

| Метод | Действие | Особенности | Применение |
|-------|----------|-------------|------------|
| `sleep()` | Останавливает поток | **Не снимает блокировки** | Задержки, опросы |
| `wait()` | Усыпляет поток | **Снимает блокировки**, ждёт `notify()` | Поставщик-потребитель |
| `join()` | Ждёт завершения другого потока | — | Когда нужны результаты |

### volatile vs synchronized

| Ключевое слово | Назначение | Особенности |
|----------------|------------|-------------|
| `volatile` | Видимость изменений для всех потоков | Не гарантирует взаимное исключение |
| `synchronized` | Синхронизация потоков | Предотвращает гонки |

### Способы использования synchronized
- На экземпляре (метод объекта).
- На статическом методе (защита статических полей).
- Внутри блока (гибкая синхронизация).

### Happens-before, memory model (JMM)
- **Happens-before** — гарантия, что результат одной операции виден другой.
- **JMM** — модель памяти Java, определяет правила видимости.

---

## 3.2. Атомарность и блокировки

- **AtomicInteger, AtomicReference** — атомарные операции без блокировок.
- **CAS** — Compare-And-Swap.
- **Проблема ABA** — значение изменилось и вернулось, CAS не замечает.
- **ReentrantLock** — явная блокировка с возможностью повторного входа.
- **ReadWriteLock** — разделение на чтение/запись.
- **StampedLock** — оптимистичные блокировки.
- **Condition** — `await`/`signal` для ожидания условий.
- **Deadlock, livelock, starvation:**
  - **Deadlock** — взаимная блокировка.
  - **Livelock** — потоки активны, но не продвигаются.
  - **Starvation** — поток не получает ресурсы.
  - **Диагностика:** thread dump, `jstack`.

---

## 3.3. Пул потоков

- **ExecutorService, ThreadPoolExecutor** — управление пулом.
- **Параметры:**
  - `corePoolSize` — базовое количество потоков.
  - `maxPoolSize` — максимальное.
  - `queue` — очередь задач.
  - `RejectedExecutionHandler` — обработка отказа.
- **ForkJoinPool** — work-stealing.
- **Почему `Executors.newFixedThreadPool` — плохая практика:** неограниченная очередь → OOM.

---

## 3.4. Высокоуровневые абстракции

- **CompletableFuture** — chaining, `thenApply`, `thenCompose`, `allOf`.
- **CountDownLatch, CyclicBarrier, Semaphore, Phaser** — синхронизаторы.
- **BlockingQueue** — реализации: `ArrayBlockingQueue`, `LinkedBlockingQueue`, `PriorityBlockingQueue`.
- **ConcurrentHashMap, CopyOnWriteArrayList** — потокобезопасные коллекции.

---

## 3.5. Виртуальные потоки (Java 21)

- **Отличие от платформенных** — легковесные, управляются JVM.
- **Pinning** — блокировка виртуального потока на платформенном.
- **synchronized vs ReentrantLock** — `synchronized` может приводить к pinning.
- **Structured Concurrency** — структурированная конкурентность.

- Идемпотентность под конкурентностью.
